# terraform-provider-leifwind

[![License: MPL-2.0](https://img.shields.io/badge/License-MPL--2.0-brightgreen.svg)](LICENSE)

A Terraform/OpenTofu provider for the **leifwind metadata API** — projects,
entities, and fields that make up leifwind's schema-per-project metadata
model. It manages the control plane only: creating/reading/updating/deleting
metadata objects against a running leifwind backend.

Registry source address: **`leifwind-io/leifwind`**.

The provider is built on a standalone, importable Go client
(`github.com/leifwind-io/leifwind-go`) with zero `terraform-plugin-*`
dependencies — see [`../go-client/README.md`](../go-client/README.md) if you
want to talk to the metadata API from your own Go code without Terraform.

## Install

```hcl
terraform {
  required_providers {
    leifwind = {
      source  = "leifwind-io/leifwind"
      version = ">= 0.1.0" # pin to the latest released version
    }
  }
}
```

The provider is distributed via GitHub Releases and resolvable from both the
[Terraform Registry](https://registry.terraform.io) and the
[OpenTofu Registry](https://registry.opentofu.org) — the same
`leifwind-io/leifwind` source address works with `terraform init` and
`tofu init` alike; no separate registry configuration is needed.

See [`docs/index.md`](docs/index.md) and [`docs/resources`](docs/resources)
/ [`docs/data-sources`](docs/data-sources) for the full provider schema and
runnable examples (generated by `tfplugindocs` — see Development below).

## Authentication

The provider supports two auth paths, mutually exclusive:

| Path | Attributes | Env var fallback | Use case |
| --- | --- | --- | --- |
| Static/delegated token | `token` | `LEIFWIND_TOKEN` | A token acquired elsewhere is handed to the provider as-is. This is the path used by leifwind's delegated apply-runner: the frontend authenticates a human user via ZITADEL, and the runner forwards that user's token unchanged, so Terraform operations are attributed to the delegating user, not a service identity. |
| `client_credentials` (M2M) | `issuer`, `client_id`, `client_secret`, `audience` | `LEIFWIND_OIDC_ISSUER`, `LEIFWIND_CLIENT_ID`, `LEIFWIND_CLIENT_SECRET`, `LEIFWIND_OIDC_AUDIENCE` | Operator/local or service-to-service use: the provider exchanges client credentials for a bearer token itself and refreshes it automatically before expiry. |

Both paths also take `endpoint` / `LEIFWIND_ENDPOINT` (the backend base URL).

```hcl
# Delegated/static token (runner path):
provider "leifwind" {
  endpoint = "https://api.leifwind.example"
  token    = var.leifwind_token # or LEIFWIND_TOKEN
}

# Alternative — client_credentials (operator/M2M path):
# provider "leifwind" {
#   endpoint      = "https://api.leifwind.example"
#   issuer        = "https://auth.leifwind.example"   # LEIFWIND_OIDC_ISSUER
#   client_id     = "…"                               # LEIFWIND_CLIENT_ID
#   client_secret = var.client_secret                 # LEIFWIND_CLIENT_SECRET
#   audience      = "326102453042806786"              # LEIFWIND_OIDC_AUDIENCE
# }
```

Complete attribute reference: [`docs/index.md`](docs/index.md).

### Known backend quirks to be aware of

- **Project names are globally unique across all tenants**, not just within
  your organization. This is intended — a consequence of the
  schema-per-project design, where each project maps to its own Postgres
  schema and schema names are database-global. Namespace project names per
  organization to avoid collisions. See
  [`docs/resources/project.md`](docs/resources/project.md).
- **FRAGMENT fields require a sibling KEY field** on the entity, enforced by
  the backend. Set `key_field_ids` on each FRAGMENT `leifwind_field` to the
  entity's KEY field id(s) so Terraform creates the KEY first and destroys it
  last — no manual `depends_on`. See
  [`docs/resources/field.md`](docs/resources/field.md).

## Development

The provider is one package of the leifwind monorepo, next to the Go client
it is built on (`../go-client`). The monorepo's root `go.work` uses both
modules, and the provider's `go.mod` has a
`replace github.com/leifwind-io/leifwind-go => ../go-client` directive, so the
provider always builds against the client's working-tree copy. The
`replace` goes once the client is published on its own.

### Local prerequisites

- **Docker** — required for `just test-go-client` (client/toxiproxy suite)
  and boot-mode `just test-provider-acceptance`; attach mode instead requires
  a running backend stack (`make stack-up stack-seed` at the monorepo root) —
  Docker is still needed once, to boot that stack via compose, just not for
  each acceptance run.
- **A backend image** for boot mode, named by `LEIFWIND_BACKEND_IMAGE`; the
  upstream's private test image needs a one-time `docker login` with a
  personal access token that has the `read_registry` scope.
- **Go ≥ 1.26**.
- **`tofu`** (OpenTofu CLI) on `PATH` — the acceptance suite drives real
  `plan`/`apply`/`destroy` cycles through it.

### Common tasks

Run from the monorepo root:

```bash
just test-provider             # provider unit tests (no Docker)
just test-go-client            # client module's full test suite (testcontainers, -p 1)
just test-provider-acceptance  # provider acceptance suite (TF_ACC=1, against tofu)
just provider-docs             # regenerate docs/ from examples/ via tfplugindocs
just go-tidy                   # go mod tidy, both modules
```

golangci-lint runs in CI (`provider:lint`, `go-client:lint`) with each
package's `.golangci.yml`.

### Fast acceptance iteration: attach mode

The acceptance suite has two ways to get a stack. **Boot mode** (default):
`leifwindtest` boots ZITADEL + backend + Postgres via testcontainers on every
run — hermetic, needs Docker, costs ~60-90 s per package. **Attach mode**:
tests attach to an already-running stack via the `LW_TEST_*` environment
contract (`stack.env`), dropping the per-run cost to seconds.

```bash
# once, at the monorepo root: boot + seed the shared stack
make stack-up stack-seed

# per iteration (the recipe sources the root stack.env)
just test-provider-acceptance
```

The tests create fixed project names and change instance-wide settings, so a
second run needs a freshly seeded stack (`make stack-reset stack-up
stack-seed`).

The dispatch is automatic: when `LW_TEST_ZITADEL_ISSUER_URL` is set (i.e.
stack.env is sourced), the suite attaches; otherwise it boots containers.
`leifwindtest.Attach()` fails fast with a contract error if `stack.env` is
incomplete or its `LW_STACK_CONTRACT_VERSION` major differs from the one the
package speaks (currently 1).

Not everything attaches: tests that mutate instance-wide ZITADEL state (and
anything using `WithToxiproxy`) need a dedicated booted stack and skip in
attach mode — CI runs them in the scheduled `provider:test-acceptance-boot`
job. In per-MR CI, `provider:test-acceptance` runs in attach mode against
GitLab `services:` and the monorepo's own backend (no Docker-in-Docker); see
`ci/provider.yml` and `docs/stack.md` for the `.leifwind-stack` template
contract.

### Monorepo primary, GitHub mirror

Development, code review, and CI live in the private leifwind monorepo.
`github.com/leifwind-io/terraform-provider-leifwind` is its public, read-only
mirror, because both the Terraform Registry and the OpenTofu Registry resolve
providers from public GitHub repositories and GitHub Releases. The mirror
runs no CI of its own — it exists purely for distribution.

## Release

The monorepo's release pipeline cuts provider releases from `provider/vX.Y.Z`
tags, after the Go client version the provider requires is published: it
pushes the scrubbed history and the plain `vX.Y.Z` tag to the mirror, then
runs goreleaser there, which builds and GPG-signs the cross-platform archives
and publishes the GitHub Release both registries index. That pipeline does
not exist yet; until it does, the provider is not released.
